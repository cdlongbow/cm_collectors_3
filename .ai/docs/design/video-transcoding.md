# 视频文件转码与源文件替换

## 功能边界

视频转码是管理员功能。用户从资源或分集右键菜单将本地视频加入数据库队列，在设置页的“视频转码”工作台调整草稿参数并开始执行。

第一版支持：

- 输出 MP4 或 MKV。
- 视频流复制、H.264、H.265。
- CRF 或目标码率、编码速度、降采样分辨率、帧率、CPU 线程。
- 音频流复制或 AAC。
- 自动探测并支持 NVIDIA NVENC、Intel Quick Sync 和 AMD AMF；未实际完成单帧编码的设备不会显示。
- 开始执行前如检测到任务可使用 GPU，会提供“全部启用 GPU 并开始”和“保持当前设置并开始”两个明确选项；关闭提示则中止启动。服务端会再次按任务的视频编码校验兼容性，并保留已经生效的 GPU 编码器。
- 字幕轨保留；MP4 输出时转换为 `mov_text`。PGS、DVD 等位图字幕会在执行前给出明确提示，需改用 MKV，源文件不会进入替换阶段。
- 单并发、队列暂停、任务取消、失败重试。
- 输出区域显示任务实际耗时；执行中按秒更新，任务结束后固定为开始至完成、失败或取消的时间。
- FFprobe 校验、安全替换、可选保留旧文件备份。
- 同步更新视频路径、技术元数据、时长和视频指纹。
- 待转码任务可打开独立的可视化剪辑工作区，进行单视频分割、删除、片段排序、转场设置和时间轴缩放。

暂不包含多视频轨精细选择、水印和定时自动转码。

## 轻量视频剪辑

剪辑入口只出现在转码列表的待转码任务操作栏。剪辑工作区复用系统播放器，并通过受管理员鉴权保护的 FFmpeg 缩略图接口展示时间轴。剪辑方案保存为任务上的版本化 JSON 快照，原视频不会在编辑阶段发生变化。

支持单个源视频的片段分割、删除、拖动排序、撤销和重做。片段之间可以设置淡白、淡黑、溶解、擦除、滑动、百叶窗、圆形展开和像素化等覆盖式转场，并可单独开启音频淡出淡入。转场由前片段尾部和后片段头部各承担一半时长，不重叠或跳过素材，因此成片总时长仍是所有保留片段时长之和。

转码执行时使用 `trim`、`atrim`、`xfade`、时间戳重置和 `concat` 过滤器在一次 FFmpeg 处理中生成最终文件。每个片段最多拆成进入动画、正常部分和退出动画，多条音轨会分别裁剪和拼接；音频淡化默认关闭。后端会校验支持的效果、0.1～3.0 秒时长，以及中间短片段能否同时容纳进入和退出转场。

剪辑预览隐藏底层源播放器的原始时间轴，以剪辑器的成片时间轴作为唯一进度。预览区提供统一的播放/暂停、静音、音量和成片进度控制；拖动进度会按当前片段排序把成片时间换算回正确的源文件时间，音量偏好保存在浏览器本地，并同步应用到普通片段和 WebM 转场预览。普通片段按当前排序连续播放；遇到转场时，服务端只渲染切点附近的 VP8/Opus WebM 并按源文件快照和转场参数缓存，播放器完成转场后从后片段的正确位置继续。转场预览缓存在服务端可执行文件所在目录的 `runtime/cache/video-transcode/transition-previews/` 下；缓存采用最近访问时间，超过 7 天或总量超过 512 MiB 时自动清理，残留的临时文件超过 1 小时也会回收。旧版用户缓存目录中的转场 WebM 会在首次使用新目录时安全清理。预览失败不会改变已保存方案或正式转码链路。

时间轴使用“片段时长 × 像素/秒”的宽度模型，支持按钮缩放、适配全部、以鼠标位置为锚点的滚轮缩放和横向滚动。播放头和鼠标定位均以片段实际 DOM 坐标计算，固定宽度转场节点不会造成累计偏移。缩略图按当前显示宽度动态分配，最多 160 张，使用 320ms 防抖、四档缓存、请求版本号和可取消的最多 4 路 FFmpeg 并发；生成期间已有缩略图继续铺满片段。

剪辑任务必须重新编码视频和音频，不能使用复制流。保存有效剪辑方案时，复制流参数会自动调整为 H.264（CPU）和 AAC；已经选择的 H.264/H.265 及其 GPU 编码器会被保留，用户仍可在保存后调整兼容参数。当前暂不处理字幕时间轴，因此含内嵌字幕轨的视频不能保存有效剪辑方案；完整视频方案仍可正常使用。暂不支持多源视频、多视频轨、变速和独立音频轨编辑。

剪辑方案可按任务选择“替换源文件”或“保存为新文件”，默认使用更安全的“保存为新文件”。新文件模式保留源文件，不更新分集路径、资源元数据和视频指纹，也不创建源文件备份；输出位于源目录，普通转码默认命名为 `{原名}_转码.{扩展名}`，剪辑任务默认命名为 `{原名}_剪辑.{扩展名}`，冲突时依次追加 `_2`、`_3`。服务端拒绝目录字符、控制字符和系统保留名称，批量应用编码参数也不会覆盖任务已经选择的输出方式和文件名。

保存剪辑方案前必须再次确认输出方式。替换模式明确提示源文件将在校验成功后被替换；新文件模式显示预计文件名并说明重名编号及源文件保留行为。取消确认会返回剪辑工作区，不写入方案或配置。

## 数据和状态

`video_transcode_tasks` 是队列的唯一事实来源。浏览器关闭不会终止后端任务，切换离开转码页面也不会产生队列数据库轮询。队列由新增、开始、继续和任务结束事件唤醒；只有数据库读取异常时才会低频延迟重试。

任务参数以 JSON 快照保存。主要状态流为：

```text
draft -> queued -> probing -> transcoding -> verifying
      -> replacing -> refreshing_metadata -> success
      -> saving_output -> success
```

异常状态包括 `failed`、`cancelled`、`interrupted` 和 `rollback_failed`。

进入 `replacing` 后不允许取消。服务启动时会清理普通中断任务的临时文件；如果在替换阶段退出且备份存在，会优先恢复旧文件，并将新输出保留为带 `.interrupted-{任务ID}` 后缀的文件。

## 文件替换协议

1. 执行前核对分集路径、文件大小和修改时间。
2. 每次执行在源文件目录创建带任务 ID 和运行 ID 的唯一 `.cmtranscode-...part` 临时输出；失败重试前只清理由本任务登记的旧临时文件。
3. FFmpeg 成功后用 FFprobe 校验文件非空、时长、视频/音频/字幕轨数量、复制流编码，以及设置的目标编码、分辨率和帧率。
   整个校验阶段另有两分钟外层看门狗；即使工具可用性检查或系统调用异常阻塞，也会结束任务、写入失败时间并保持源文件不变。
4. 替换期间先封锁该源路径的新 Range/HLS 播放请求，再取消已有请求、关闭服务端播放文件句柄并清除视频信息缓存，避免播放器错误重连反复抢占读锁。独占锁按 5 秒一轮自动重试 3 次；仍失败时保留源文件和已校验的临时成片。
5. 将源文件重命名为带任务 ID 和运行 ID 的临时 `.cmbackup-...` 回滚文件；这是安全替换的必要步骤，与是否“保留备份”无关。
6. 将临时输出重命名为正式文件。
7. 在同一个数据库事务中更新分集路径、时长、视频元数据、视频指纹和任务成功状态。
8. 数据库事务失败时恢复旧文件；事务提交后再按任务参数保留或删除备份。此时清理备份失败只记录警告，不会把已经成功替换的任务误报为失败。
9. 手动移除任务时，仅在临时文件名包含当前任务 ID、以 `.part` 结尾且与源文件同目录时同步删除该文件；删除资源时自动删除其草稿和失败转码任务，成功历史及活动任务不受影响。

替换成功后的播放地址携带由文件大小和修改时间生成的媒体版本号，避免浏览器沿用替换前的媒体响应。若播放器恰好在替换时被中止，自动重试会追加一次性刷新参数并重建请求。

因播放句柄或 Windows 文件共享冲突而失败的任务会显示“重试替换”和“保存为新文件”。两种操作都不会重新编码，而是重新核对源文件快照、临时文件归属与大小，并用 FFprobe 再次校验临时成片；前者只执行安全替换和元数据刷新，后者保留源文件并发布为自动编号的新文件。临时成片、源文件或备份状态有变化时必须拒绝复用。

容器变化时正式文件扩展名随之变化，分集 ID 保持不变，因此标题、演员、标签、封面和播放历史不会丢失。

## API

管理员 API 前缀为 `/api/videoTranscode`：

- `GET /list`
- `GET /capabilities`
- `POST /add`
- `PUT /config`
- `PUT /editPlan/:id`
- `GET /thumbnail/:id?at={秒}`
- `POST /thumbnails/:id`
- `POST /transitionPreview/:id`
- `POST /start`
- `POST /resetBatch`
- `POST /pause`
- `POST /resume`
- `GET /status`
- `POST /cancel/:id`
- `POST /deleteBatch`
- `DELETE /delete/:id`

`start` 和 `config` 的 `ids` 为空时表示处理全部符合状态的任务，因此前端在存在勾选项时必须传递过滤后的明确 ID，不能用空数组回退为“全部”。
