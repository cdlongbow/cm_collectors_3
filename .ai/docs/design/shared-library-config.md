# 文件库公共基础配置

## 范围与交付

一期：基础展示配置跟随，完成后独立 Git 提交。二期：导入规则、资源刮削参数跟随，再独立提交。没有模板系统、标签复制或标签同步。

用户显式将当前参数设为公共配置。各分组只有一份公共配置；旧库默认独立，新库可选择跟随。公共配置只能通过“编辑公共配置”入口更新，保存前列出关联库。停止跟随时保留当前生效参数。

## 边界

- 共享字段由后端 `SharedConfigFields` 白名单定义，前端用同一份字段列表锁定表单。
- 标签和演员引用、目录、路径映射、自定义头像、封面预设列表及索引始终属于本库。
- 公共参数单独存储；跟随关系单独存储。升级只增加表，不批量重写旧配置。
- 普通读取按需叠加公共值，独立库保留原始 JSON 和空配置语义。
- 普通写入不更新公共配置；跟随中提交不同公共参数会被后端拒绝。
- 首页快捷调整明确提示关闭本库展示跟随；取消时恢复服务端生效值。
- 公共更新带版本校验，旧页面不能静默覆盖新版本。不提供删除公共配置入口。
- 启用、退出跟随和新建库关联均在事务内执行；删除空库清理跟随关系。
- 套用配置不自动启动任何导入、刮削或计划任务。当前页面切换文件库或重新加载时获取最新公共值。

## 验证

使用内存 SQLite 检查独立库不变、多个跟随库更新、本地引用保留、退出后保持参数、版本冲突、失败事务回滚、旧空配置语义。前端做类型检查、构建及交互测试。

开发前基线：`go test ./models ./processors ./controllers` 的 processors 包有已存在的 LogError 非常量格式串 vet 错误；`yarn.cmd type-check` 已存在 require、textAlign 和 coverAdjuster 显示模式类型错误。记录基线后以新增错误为回归判断，运行 Go 测试时可使用 `-vet=off` 单独确认测试结果。

一期验证：后端 models/processors/controllers 测试在 `-vet=off` 下通过；新增前端交互测试 3 项通过；`yarn.cmd build-only` 通过；类型检查无新增错误，仍受上述基线问题影响。
